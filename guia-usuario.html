Normalizador de Contratos DMS

Andreani · Guía de Usuario

Una herramienta simple para validar y normalizar contratos DMS

🤔 ¿Qué hace esta herramienta?

Esta herramienta está diseñada para automatizar y simplificar el proceso de preparación de contratos DMS para la plataforma Andreani.

¿Qué problema resuelve? El archivo Excel que recibes tiene información desordenada, fórmulas que deben convertirse a valores estáticos, y datos que necesitan ser validados y normalizados antes de ser procesados por el sistema.

¿Qué hace exactamente?

  • ✅ Valida que los campos del formulario sean correctos
  • 🔄 Convierte todas las fórmulas a valores estáticos
  • 🗑️ Elimina la hoja Formulario (solo se usa para la carga)
  • 📑 Organiza la hoja Referencias al final
  • 🏢 Limpia las direcciones vacías
  • 📝 Renombra el archivo con los datos del contrato
  • 💬 Genera un mensaje listo para copiar

📋 Reglas de validación y normalización

La herramienta verifica automáticamente que los datos ingresados sean correctos y normaliza aquellos valores que tengan errores comunes de tipeo, acentuación o mayúsculas/minúsculas.

📌 CodigoContratoERP (C3)
✅ 9 dígitos
Ej: 351005959
📌 IDSociedadSAP (C7)
✅ Debe ser "1100"
Para B2B siempre es 1100
📌 Habilitado (C8)
✅ 1 o 0
1 = Activo, 0 = Inactivo
📌 Campos booleanos
✅ true/false, 1/0, si/no
AllowRescue, ObligatoryGauge, etc.
📌 Normalización automática por diccionario de sinónimos
La herramienta corrige automáticamente errores comunes de tipeo en los siguientes campos:
  • TipoDeEnvio: "paqueteria" → "Paquetería"
  • TipoDeEnvio: "logistica inversa" → "Logística inversa"
  • HasDeliveryNote: "con remito" → "CON_REMITO"
  • HasDeliveryNote: "sin remito" → "SIN_REMITO"
  • Logística Solicitada, Continente, SLA, FormularioMobileB2B: normaliza mayúsculas, minúsculas y acentos
📌 HasDeliveryNote — Normalización automática:
true / 1 / si → CON_REMITO
false / 0 / no → SIN_REMITO
con remito / CON_REMITO / ConRemito → CON_REMITO
sin remito / SIN_REMITO / SinRemito → SIN_REMITO
digitalizado / DIGITALIZADO / Digitalizado → DIGITALIZADO
🔢 Normalización de CodigoSolicitanteERP

El campo CodigoSolicitanteERP (C5) puede llegar en diferentes formatos. La herramienta lo normaliza automáticamente:

✅ Válido
6 dígitos
Ej: 123456
🔄 Normalizado
10 dígitos con 4 ceros
0000120761 → 120761
❌ Inválido
10 dígitos sin 4 ceros
1234567890 → ❌ Error
❌ Inválido
Menos de 6 o más de 10
12345 o 12345678901 → ❌ Error
🏢 Limpieza de direcciones

Si el ejecutivo solo completó algunas direcciones, la herramienta elimina automáticamente las filas vacías de la hoja Direcciones.

📋 Ejemplo:
ANTES Street | City | AddressType Amado Aufranc | ESPERANZA | 1 0 | 0 | 2 ← vacía 0 | 0 | 3 ← vacía Amado Aufranc | ESPERANZA | 7 0 | 0 | 8 ← vacía
⬇️
DESPUÉS Street | City | AddressType Amado Aufranc | ESPERANZA | 1 ← se conserva Amado Aufranc | ESPERANZA | 7 ← se conserva
✅ Solo se conservan las filas que tienen al menos un campo con información real
📝 Nombre de archivo personalizado

La herramienta renombra automáticamente el archivo de salida con los datos del contrato:

Alta de contrato DMS 351005959 120761 NOISACO SA.xlsx
  • Alta de contrato DMS → Texto fijo
  • 351005959 → CodigoContratoERP (C3) — Obligatorio
  • 120761 → CodigoSolicitanteERP (C5) — Obligatorio
  • NOISACO SA → ClientName (C14) — Opcional

📖 Normalización por diccionario de sinónimos

La herramienta incluye un diccionario de sinónimos que permite corregir automáticamente errores comunes de tipeo en los campos con valores predefinidos.

¿Cómo funciona?

  • 🔍 Detección: Identifica valores que no coinciden exactamente con los valores válidos
  • 🔄 Corrección: Busca en el diccionario de sinónimos y aplica la corrección automática
  • 📝 Registro: Todas las correcciones se registran en el log para trazabilidad
  • ❌ Error: Si el valor no se reconoce, muestra un error con la lista de valores válidos
📋 Ejemplos de normalización:
Campo: TipoDeEnvio ❌ "paqueteria" → ✅ "Paquetería" ❌ "logistica inversa" → ✅ "Logística inversa" ❌ "cadena de frio" → ✅ "Cadena de frío" ❌ "retira deposito" → ✅ "Retira depósito" Campo: HasDeliveryNote ❌ "con remito" → ✅ "CON_REMITO" ❌ "sin remito" → ✅ "SIN_REMITO" ❌ "CONREMITO" → ✅ "CON_REMITO" ❌ "digitalizado" → ✅ "DIGITALIZADO"
💡 Beneficios:
✅ Reduce errores por tipeo manual
✅ Acepta valores sin acentos o con mayúsculas/minúsculas incorrectas
✅ Mejora la experiencia del usuario
✅ Mantiene la trazabilidad con logs de normalización
